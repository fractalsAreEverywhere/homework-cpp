# Разбор ДЗ 3 для защиты

## 1. Что хранит SparseMatrix

rows_ и cols_ задают размеры, даже если матрица целиком нулевая.
data_ связывает координаты (i,j) с числом double. set удаляет запись,
если записываем ноль. get использует find: чтение отсутствующего элемента
возвращает ноль и не меняет контейнер. Оператор [] для такого чтения
не подходит: он вставил бы отсутствующий ключ.

Для записи map: entry.first — пара координат, entry.second — число.
entry.first.first — строка, entry.first.second — столбец.

## 2. Что изменилось относительно нашего первого класса

У каждого класса свой заголовок: matrix.h, dense_matrix.h, sparse_matrix.h.
В заголовке находятся поля класса и объявления методов без тел.
Тела методов находятся в соответствующих .cpp: matrix.cpp, dense_matrix.cpp
и sparse_matrix.cpp. Каждый .cpp компилируется один раз для программы,
поэтому для этих определений не требуется inline.
Запись DenseMatrix::get означает «метод get класса DenseMatrix».
В начале каждого заголовка стоит #pragma once: повторное подключение
не приводит к повторному описанию класса внутри одного .cpp.
Заголовки Dense и Sparse не подключают друг друга. Запись class SparseMatrix;
заранее сообщает о существовании класса, чтобы объявить параметр-ссылку.
Полные описания обоих классов подключены в .cpp, где используются их методы.
Подключать .cpp через #include не нужно: они перечислены в настройках сборки.

const после метода обещает не менять исходную матрицу.
const Matrix& принимает матрицу без копирования и запрещает её менять.
auto выводит тип переменной; const auto& в цикле читает запись map
по ссылке, не создавая копии.

Проверка индексов запрещает отрицательные и выходящие за размеры координаты.
Проверка размеров выполняется до умножения.

## 3. Преобразования

toDense создаёт нулевую плотную матрицу и переносит в неё записи map.
Создание плотной матрицы уже занимает память и время на все её ячейки.

fromDense просматривает все ячейки плотной матрицы и сохраняет ненулевые.
static означает, что для вызова не нужен существующий объект SparseMatrix:
SparseMatrix::fromDense(dense).

## 4. Четыре умножения

Во всех случаях вычисляется C[i,j] += A[i,k] * B[k,j].

- Dense×Dense: циклы i-k-j, последовательный обход строк B и C.
- Sparse×Dense: берём ненулевой A[i,k] и умножаем его на строку k из B.
- Dense×Sparse: берём ненулевой B[k,j] и добавляем его вклад
  в каждый элемент столбца j результата.
- Sparse×Sparse: берём ненулевой A[i,k] и ненулевые элементы строки k из B.

Для Sparse×Sparse map упорядочена по паре координат.
lower_bound({k,0}) находит первую запись с ключом не меньше (k,0).
Идём вперёд, пока номер строки равен k. Если строка пуста,
внутренний цикл не выполняется. Это позволяет пропустить нули B.

Dense×Dense и смешанные сочетания возвращают DenseMatrix.
Sparse×Sparse возвращает SparseMatrix; нулевые суммы удаляются через set.
Разреженные входы могут дать плотный результат: это допустимо.

## 5. Диспетчеризация и память

Виртуальный mul выбирается по настоящему типу первой матрицы.
Внутри метода dynamic_cast проверяет тип второй.
Для неподходящего типа указатель равен nullptr, тогда проверяем другую ветку.

std::unique_ptr<Matrix> владеет результатом. make_unique создаёт объект,
а указатель автоматически освобождает его при окончании времени жизни.
Виртуальный деструктор обеспечивает корректное удаление наследника.

## 6. Почему такие тесты

Ручной пример задаёт ответ независимо от алгоритмов.
Кросс-проверка сравнивает четыре представления с наивным плотным i-j-k.
Размеры специально неквадратные, есть пустые строки, нули,
отрицательные и дробные числа. Сравнение double выполняется с допуском 1e-9.
Функция require бросает исключение при ошибке, main печатает сообщение
и возвращает ненулевой код, который CTest считает провалом.

ASan ищет ошибки памяти в выполненных участках; правильность чисел
проверяют сами тесты. Успешный запуск не доказывает отсутствие всех ошибок.

## 7. Что сказать о производительности

Для Dense×Dense работа O(m*n*p).
Для Sparse×Dense арифметических операций порядка nnz(A)*p.
Для Dense×Sparse — порядка m*nnz(B).
Для Sparse×Sparse число вкладов зависит от ненулевых элементов
сочетающихся строк; поиск и обновления map дополнительно стоят логарифмическое время.
Результат тоже может стать плотным, так что Sparse не всегда быстрее.

Бенчмарк использует Release без ASan, одинаковые входы, прогрев и повторы.
Нужно объяснить наблюдаемый переход по таблице, не обещая универсального порога.
